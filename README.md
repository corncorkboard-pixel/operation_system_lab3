# process_demo.c

fork() - `повертає різні значення батькові й нащадкові Системний виклик fork() створює точний дублікат поточного процесу. Після його виклику операційна система має розрізняти два процеси, що виконують один і той самий код з однієї й тієї самої точки. Батьківському процесу fork() повертає PID (ідентифікатор) створеного нащадка. Батько має знати, кого він створив, щоб контролювати його. Процесу-нащадку fork() повертає 0. Нащадок завжди може дізнатися свій PID через getpid(), тому йому не потрібно повертати власне ID.`

execlp - `код після нього не виконується. Функція execlp замінює поточний образ процесу новою програмою. Що вона робить: Шукає програму echo в системних директоріях (завдяки суфіксу p, який використовує змінну оточення PATH), завантажує її в пам'ять поточного процесу, затираючи старий код С, і передає їй керування. Чому код після неї не виконується: exec не створює новий процес, він трансформує поточний. Оскільки код поточної програми в пам'яті повністю знищується та замінюється кодом echo, рядки з perror("execlp") та _exit(127) фізично зникають із пам'яті процесу-нащадка. Вони виконаються лише у випадку помилки, якщо execlp не зможе знайти або запустити програму.`

waitpid(pid, &status, 0) - `Цей рядок змушує батьківський процес призупинити своє виконання (заблокуватися) доти, доки процес-нащадок із вказаним pid не змінить свій стан (не завершиться). pid: ID конкретного нащадка, завершення якого чекає батько. &status: Вказівник на змінну, куди ОС запише інформацію про те, як саме завершився нащадок (код виходу, чи був він убитий сигналом тощо). Потім ці дані розшифровуються макросами WIFEXITED та WEXITSTATUS. 0: Прапорці (options). Значення 0 означає дефолтну поведінку — синхронне очікування повного завершення процесу без додаткових умов.`

fflush(NULL) - `Стандартна бібліотека C (stdio.h) використовує буферизацію вводу-виводу для оптимізації роботи з диском та терміналом. Перед fork(): Коли виконується printf("Батько:..."), текст не виводиться на екран миттєво, а зберігається в буфері пам'яті процесу (особливо якщо вивід перенаправлено у файл, де використовується блочна буферизація, а не рядкова). Під час fork() весь цей буфер копіюється в нащадка. Якщо буфер не очистити, рядок "Батько:..." буде надрукований двічі: спочатку батьком, а потім нащадком (або буде втрачений під час exec). Перед exec(): Якщо нащадок щось запише в буфер printf і викличе exec, ОС повністю очистить оперативну пам'ять процесу під нову програму. Усі нескинуті буфери printf буде назавжди втрачено. fflush(NULL) примусово записує всі дані з буферів у системний термінал безпосередньо перед тим, як пам'ять буде стерто.`

# worker_children.c

Нащадок 0 та 2: `Вони успішно виконують системний виклик _exit(10 + i). Макрос WIFEXITED(status) повертає істину, а WEXITSTATUS(status) витягує переданий код (10 для нащадка 0 та 12 для нащадка 2).`

Нащадок 1: `У коді процесу-нащадка стоїть умова if (i == 1) { abort(); }. Функція abort() генерує сигнал SIGABRT (сигнал аварійного завершення, зазвичай номер 6). Оскільки процес перервано сигналом, макрос WIFEXITED повертає брехню, а спрацьовує WIFSIGNALED(status), який через WTERMSIG(status) виводить номер цього сигналу`

`звіт батька завжди друкується строго по порядку: від 0 до 2. Чому так відбувається: У другому циклі батьківський процес викликає функцію waitpid(pids[i], &status, 0). Параметр pids[i] змушує батька чекати завершення конкретного нащадка у фіксованій послідовності індексів (i = 0, потім i = 1, потім i = 2). Навіть якщо нащадок 2 завершить свою роботу раніше за нащадка 0, батьківський процес заблокується на ітерації i = 0 і чекатиме саме першого нащадка. Лише після отримання статусу нащадка 0, цикл перейде до i = 1, а потім до i = 2 (де статус нащадка 2 буде зчитано миттєво, оскільки той уже завершився). Порядок виведення на екран повністю детермінований логікою виклику waitpid за конкретними PID.`
